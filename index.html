What you can do

Observability

Explore vSphere inventory
Browse clusters, hosts, VMs, and datastores. Use DBH Insights to review capacity and download inventory as XLSX or CSV.
Monitor health and logs
Track host health and datastore capacity, map storage dependencies, and search syslog messages or send alerts to named webhooks.

Collectors store data in SQLite. Use the token-protected REST API to pull collected data into Management Pack Builder.
Put the lab on a wall display
Apple HomeView cycles through lab dashboards and can show the latest answer from a scheduled Ask prompt.

MCP & Salt in Ask

Model Context Protocol (MCP) connects Ask to tools that can inspect your lab as you chat. Tool results appear as numbered sources you can open and verify.

MCP tool calls

Use a host-side tool server
The Ask container sends token-protected requests to the Ask host agent. The agent runs servers from your .mcp.json over standard input and output, so they can use the host's PowerShell modules and lab configuration.
Query live lab systems
Dale's PowerShell server exposes 39 tools, including vCenter snapshot audits, VCF Operations metrics and alerts, switch diagnostics, and Salt checks.
Choose what can run
Read-only tools default to Allowed. Actions such as sending email, updating DNS, or writing a report default to Ask first and wait for Run in chat. Set a tool to Off to hide it from the model.
MCP setup and policies on GitHub ↗

20 read-only Salt tools

Inventory and correlate minions
See which Salt minions respond, look up their grains such as OS and hardware, and match them to vCenter VMs by BIOS UUID, name, hostname, or IP.
Inspect Linux and Windows guests
Check uptime, memory, disks, interfaces, services, installed packages, and pending updates. Compare VMware Tools versions inside a guest with vCenter.
Review jobs and configuration drift
Look up running jobs, history, and results. Get-Salt-Config-Drift previews state changes with test=True. Target a specific minion, a pattern such as web*, or a comma-separated list.

Set up MCP and Salt on macOS
  1. Start Ask and choose an Ollama model with tool-calling support. Have a local MCP server with a stdio entry in .mcp.json. To use Dale's Salt tools, configure the PowerShell server with access to your Salt master and its minions. The example reads lab connection settings from Home-Lab-Config.yaml beside the MCP folder.
  2. From the vCommunity Observability repository, install the Ask host agent with the path to your MCP config. 
    ./ask/agent/install.sh --mcp-config /path/to/.mcp.json
  3. Put the installer’s ASK_AGENT_TOKEN in .env and recreate the Ask container. The default host agent URL is http://host.docker.internal:9101. 
    docker compose up -d vco-ask
  4. In Ask, open MCP tools under Knowledge. Verify that your server is running and review its tool policies. In a new chat, select Sources → Tools: <server>.

Try asking which Linux VMs have pending kernel updates or which Salt states would change on web*.

Run it on your computer

Complete the shared steps, then follow the setup for one or both apps.

  1. Install Git and Docker Compose

    Install Git and a container engine. On macOS or Windows, start Docker Desktop or start Rancher Desktop with the dockerd (moby) engine. On Linux, install Docker Engine and the Compose plugin.

    Git Docker Desktop Rancher Desktop Docker Engine Compose plugin 
    git --version
docker compose version

  2. Clone the repository

    git clone https://github.com/dalehassinger/vCommunity-Observability.git
cd vCommunity-Observability

  3. Copy the configuration and set a token

    Create config/config.yaml and .env before starting Docker. Copy the generated token into .env as VCO_API_TOKEN_MPBUILDER for Observability or ASK_API_TOKEN for Ask. Generate a separate token for each app you run.

    cp config/config.example.yaml config/config.yaml
cp .env.example .env
openssl rand -hex 32
    Copy-Item config/config.example.yaml config/config.yaml
Copy-Item .env.example .env
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$bytes = New-Object byte[] 32
$rng.GetBytes($bytes)
$rng.Dispose()
-join ($bytes | ForEach-Object { $_.ToString('x2') })

    Keep .env private.

Set up Observability

Shared steps ↑

  1. Enable sample data

    Uncomment VCO_MOCK=1 in .env to try the dashboards before connecting vCenter. If your container engine restricts port 514, add SYSLOG_PORT=1514.

  2. Create folders and start Observability

    mkdir -p data exports extra-modules control
chmod 777 control
if [ "$(uname -s)" = Linux ]; then
  sudo chown -R 10001 data exports extra-modules
fi
docker compose up -d --build vco
docker compose ps
    New-Item -ItemType Directory -Force data, exports, extra-modules, control | Out-Null
docker compose up -d --build vco
docker compose ps

    Wait for vco to report healthy.

  3. Open the dashboards

    Visit localhost:8080. In Modules & API, select Run collectors now for a module and enter your token if prompted. Open a dashboard from the sidebar.

    Connect a live vCenter

    Remove VCO_MOCK=1 from .env and rerun docker compose up -d vco. Add your vCenter address and read-only credentials under Settings → Connections, then select Save and test. Enable SSL verification when vCenter has a trusted certificate.

Set up Ask

Shared steps ↑

  1. Install Ollama and pull models

    Install Ollama on your computer, then follow the networking instructions for your OS so the Ask container can reach it.

    Download Ollama ↗ Ollama networking ↗ 
    ollama pull nomic-embed-text
ollama pull qwen3:8b

    Set ASK_CHAT_MODEL=qwen3:8b in .env to use this example. Choose a model that fits your computer's memory.

  2. Create folders and start Ask

    mkdir -p ask-data ask-knowledge ask-sources exports control
chmod 777 control
if [ "$(uname -s)" = Linux ]; then
  sudo chown -R 10002 ask-data
fi
docker compose up -d --build vco-ask
docker compose ps
    New-Item -ItemType Directory -Force ask-data, ask-knowledge, ask-sources, exports, control | Out-Null
docker compose up -d --build vco-ask
docker compose ps

    Wait for vco-ask to report healthy.

  3. Index a source and ask a question

    Visit localhost:8081, enter your Ask token, and select Settings → Test connection. Go to Knowledge sources → Add source, wait for the sync, then select the source in New chat.

    In an empty question box, press ↑ or ↓ to revisit earlier questions from that chat.

    Start with a PDF

    Choose PDF documents as the source type, save it, then upload a product guide or runbook. Ask a question about it and open a citation to check the relevant page.

    Connect MCP and Salt tools ↑

To stop the containers, run docker compose down from the repository folder.
